## 构建方式

从产品目录运行：

```powershell
./scripts/build.ps1 -development -out build/debug
./scripts/build.ps1 -development -action check -out build/input-check
```

从工作区根运行：

```powershell
./aTrustHub/scripts/build.ps1 -development -out build/debug
```

Linux/macOS 或 Git Bash 使用 `bash scripts/build.sh`，参数相同。`-os`、`-arch` 指定目标，`-worker` 显式指定 Worker 检出，`-inputs` 可指向同一份固定输入文件来构建历史产品提交。
相对输出路径始终相对于 `-root` 指定的产品目录。

正式打包仍使用 `package-windows.sh`、`package-linux.sh`、`package-mac.sh`，这些脚本调用同一个构建工具。
默认要求干净的产品源码；本地开发可传 `-development`，打包脚本对应 `EASYCONNECT_DEVELOPMENT_BUILD=1`，并在 manifest 中保留脏文件状态。
Worker 在开发和正式构建中都必须处于固定提交且没有未提交源码。

固定输入位于 [build-inputs.json](../../packaging/build-inputs.json)：Go `1.27.4`、Worker 提交 `9f433a0`、当前内置内核树 `58f9689`。
产品提交由实际检出记录，不把自身提交号硬编码进同一个提交。

工具显式设置 `GOWORK=off`、`GOFLAGS=-mod=readonly`、`GOTOOLCHAIN=local`、目标架构和编译选项。
当前阶段 Hub 保持上游 uTLS `v1.8.2`、内置 zju-connect；Worker 保持自己的 patched uTLS。解析到其他来源时构建失败。
`go.work`、`go.work.sum` 的原文件保留，构建不依赖它们。

每份输出包含：

- `build-manifest.json`：固定输入、实际产品/Worker 提交、开发状态、编译参数、组件及 SHA-256。
- `desktop-modules.json`、`worker-modules.json`：两侧完整模块解析结果，包括本地替换路径。
- 平台二进制和资源；正式发行的许可证、协议自检和整体校验清单继续由打包脚本负责。

从产品目录和工作区目录各执行一次 `-action check`，两侧模块清单的 SHA-256 完全相同；Git Bash 入口也已执行。

## Windows 受控空闲结果

使用 [measure-idle.ps1](../../scripts/measure-idle.ps1) 启动独立配置；接管、更新和分享明确关闭，无网关、无凭据。
预热 5 秒后隐藏本次创建的窗口，按名义 500 毫秒间隔采集 20 秒；进程枚举也有耗时，因此每次得到 26–30 个样本。
隐藏时间未达到原有 30 秒工作集修剪阈值。两版本交替运行，各 3 次。

```powershell
./scripts/measure-idle.ps1 `
  -Executable ./build/p0/binaries/relay/connect-hub.exe `
  -OutputDirectory ./build/p0/measurements-controlled/relay-new
```

需要采集已运行场景时使用 [measure-process-tree.ps1](../../scripts/measure-process-tree.ps1)，指定根 PID；它只读取计数，不终止进程。
采集器按创建时间辨识进程和后代，拒绝根进程退出/PID 复用；记录 Private Bytes、Working Set、句柄、累计 CPU 和窗口状态。
共享系统服务不计入；采样间隔内退出的短任务可能漏采，Working Set 的跨进程求和也可能重复计算共享页。

| 版本/轮次 | Private Bytes 中位数 MiB | Working Set 中位数 MiB | 最大句柄数 |
|---|---:|---:|---:|
| dev-main / 1 | 165.40 | 111.60 | 1512 |
| dev-main / 2 | 169.00 | 114.77 | 1512 |
| dev-main / 3 | 164.66 | 112.21 | 1512 |
| relay / 1 | 170.85 | 115.35 | 1500 |
| relay / 2 | 166.78 | 111.76 | 1486 |
| relay / 3 | 170.02 | 115.49 | 1504 |

六次样本均只有 Hub 进程；无 VPN 会话，所以没有 Worker 常驻。三轮中位数再取中位数，Private Bytes 为 165.40 与 170.02 MiB，差约 4.62 MiB。
单版本轮间波动约 4 MiB，这个小样本不能用来推断所有用户的增幅，更不能证明泄漏。后续比较应复用相同配置、窗口状态和负载。

## 生命周期反馈与预算

`TestUnusedSharingHasNoBackgroundTasks` 沿 `newApp` 使用的分享装配路径检查实际工作协程，优化前失败：

```text
unused sharing started 3 background tasks:
relay.(*Controller).loop
discovery.(*Publisher).loop
(*app).setupLANDiscovery.func6
```

该回归测试随 P1 修复提交，P0 先保存失败证据。
诊断测试 `TestOptionalResourceBaseline` 覆盖未使用、打开面板、浏览、启用分享与发布、停用、连续 10 轮、最终退出。
它使用真实控制器与本地监听、替代 VPN 和组播后端，不访问真实网关或操作防火墙。

```powershell
$env:GOWORK = 'off'
$env:CONNECT_HUB_MEASURE_RESOURCES = '1'
go test -run '^TestOptionalResourceBaseline$' -count=3 -v .
```

首次三次诊断运行均通过。停用后仍保留默认启动的协调循环；诊断中的 goroutine 总数包含测试和 GUI 工作，不用总数单独判断泄漏。
GC 后堆指标与原生进程的 Private Bytes/Working Set 分开解释；诊断代码显式记录 GC 点，不将其作为产品回收逻辑。

在后续行为修改前确定以下门禁：

- 未使用时，功能专用常驻任务与监听为 0；这是一项确定性要求，不以总内存噪声豁免。
- 连续 10 次启停后，活动任务、连接与句柄不随轮次持续增长；停用需等待运行资源结束，保留恢复与内网归属保护。
- 固定替代后端场景的完整停止目标为 1 秒内；故障/不合作后端按现有有界取消和清理预算验证，不能用正常路径时延代替。
- 三轮空闲 Private Bytes 中位数相对同环境基础版增加超过 `max(8 MiB, 基础版的 5%)` 时视为需要分析的回归信号。本次基础值对应约 8.27 MiB；这不是承诺达到的节省量。
- 反复启停的 GC 后保留堆相对界面预热后基线超过 2 MiB 时采集分配剖析并查明归属，不能仅靠强制 GC/工作集修剪宣告通过。

预算依据是本次小样本噪声和可确定的生命周期边界，后续真实负载若需要调整，应先记录证据和原因再调整门禁。
