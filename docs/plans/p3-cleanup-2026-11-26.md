## 实现边界

- Hub 生产依赖图不包含 cleanup service。页面只使用 client/contract，并在 UI 线程消费单槽快照；构造和打开页面不启动任务，不在绘制时读取报告或扫描。
- 四类重操作均在独立程序中执行。扫描/查询不主动提权；执行/恢复先探测能力，再请求 UAC。版本不兼容和缺失组件显示独立状态。
- 任务通过私有目录交换有界 JSON。Windows 在创建目录时设置受保护、可继承的 ACL，仅允许发起用户、管理员和 SYSTEM。每任务随机目录；计划、增量事件和修改日志各自保存。禁止路径链接进入任务目录。
- 握手包含版本、能力和随机实例 ID；请求包含请求 ID、截止时间，事件包含单调序号和终态。拒绝旧实例、旧请求、重复、乱序和超限消息。单消息 64 KiB，任务进度流 8 MiB；GUI 只保留有限摘要。
- 报告按偏移增量读取，只保留一条未完成行。没有新事件时不重复复制 GUI 快照。Windows 文件共享冲突只做最长约 250ms 的重试，不吞掉权限或格式错误。
- 每秒更新任务租约；Hub 消失超过 15 秒或发出取消请求时，组件进入同一安全取消路径。清理/恢复不会被 GUI 强杀。已有系统命令可能推迟完成当前步骤，因此不承诺修改任务在固定一秒内退出。
- 修改操作先保存备份，在每项操作前刷盘记录 intent，结果随后刷盘。取消在项间检查；缺少最终结果视为未确认完成。查询备份时提示未完成的历史修改任务，不自动重试。OS 文件锁阻止同一备份目录的并发修改任务。
- GUI 完成后释放进程句柄、定时器和监听任务；扫描详情仅供当前页面选择使用，关闭后解除引用。修改记录与备份由组件持有，不随 GUI 状态释放删除。

## 备份与兼容修正

移植时发现原实现会忽略部分备份错误并仍继续删除，已改为备份失败则停止。超过单文件备份上限不再静默跳过；新增随机备份 ID，区分注册表 32/64 位视图和证书存储范围；恢复文件先写同目录临时文件、刷盘后替换，并核验已有 SHA256。恢复前拒绝越界和链接备份路径。已有 CLI 和 manifest 格式保持可读取。

这些改动不把原有备份升级为系统镜像。驱动/服务/Winsock 等仍可能需要重新安装，页面和使用文档已取消“全量无损一键还原”的承诺。
